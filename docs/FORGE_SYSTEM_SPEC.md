# 锻造系统规格：八类能力与原始状态

> 状态：R1 当前权威产品规格。
> 目标：证明一套源码层可迁移的锻造交互基础成立，不宣称完整武器制造、完整游戏玩法、工业材料仿真或可售 SDK 已成立。
> 范围：玩家操作金属工件；剑、斧、匕首等成品语义以及攻击力、六维、故事和魔法属性都属于下游。

## 0.1 工坊世界与参考图约束

锻造发生在低魔法、早期机械化时代。设备可以由水力、蒸汽、齿轮、皮带、配重或魔法动力提供较强性能，但视觉上必须仍像铸铁、木材和铜件组成的可维护工坊设备。不得把设备默认表达成现代电动工业机器。

八类工位共享同一间连续工坊。参考图可以改变镜头位置并突出一个工作台，但应保持木桌、石墙、冷暖光源、材料架和整体比例的一致。R1 采用低集合体几何，参考图首先确认正交关系、接触关系、操作对象和空间布局；精细建模属于后续工作。

## 1. 原始状态是唯一事实源

玩家操作只能改变可序列化的 `ForgeState`。渲染读取 `ForgeSnapshot`，下游规则读取 `ForgeFacts`，二者都不能反向改状态。

| 状态类别 | 当前事实 | R1 含义 |
| --- | --- | --- |
| 材料 | 工件级降阶材料摘要；每个 block 的 `materialId`、`materialRegionId` | 既能支持现有公式，也不丢失切割、焊合后的来源区域 |
| 几何与质量 | 点阵节点、截面、block 体积、总长、重心 | 锤击产生局部连续形变；切割、焊合和研磨保持可解释的质量变化 |
| 热状态 | 当前温度、峰值、热暴露、氧化和过热剂量 | 加热和冷却影响后续操作条件 |
| 工艺历史 | 有序的淬火、回火事件 | 保存介质、起始温度和回火温度，供未来材料模型与下游读取 |
| 力学状态 | 塑性应变、弹性应变、残余应力、机械功、损伤、裂纹 | 风险来自材料、温度、载荷和支撑，不来自简单敲击计数 |
| 表面与去料 | 研磨覆盖、均匀度、累计去除体积 | 研磨会减少质量，而不是只增加一个“锋利分” |
| 界面 | `joints[].contactArea`、焊合温度、完整性 | 焊合质量作为原始事实保存，R1 不替下游解释成某种缺陷或属性 |
| 版本 | `stateVersion`、`parameterVersion` | 区分存档结构与规则参数，支持确定性回放和后续迁移决策 |

当前工件的 `material` 是供降阶公式使用的体积加权摘要，不表示不同材料已经物理均质化。空间材料来源以 block 为准。

## 2. 八类顶层能力

八类是玩家能力分类，不是八个“一点就结算”的按钮。每个工作站必须有实际输入过程、因果状态变化和可见结果；玩家可以自由决定顺序并承担不合适操作的后果。

### 2.1 选料

- 选择已定义材料并把新工件加入工作台。
- 不替换或丢失当前工件；玩家通过工件 HUD 明确切换加工对象。
- 不同材料参数必须真实进入后续热和力学公式。

当前选料验收采用三种固定规格钢料：低碳钢、高碳钢和弹簧钢。桌面点击仅查看，候选钢料前移，显示材料表中的碳含量和尺寸、密度计算的质量；确认领取才创建独立工件，取消不改变锻造状态。材料来源可重复领取，当前没有费用或库存消耗。

单项选料入口从空料架开始，首件确认时才创建该会话的锻造状态；核心仍要求一个当前工件，不引入空工件状态。后续领取只加入工作台，不替换正在加工的工件。实体料架读取工件快照，每页展示四件，分页不限制总量，切割产物仍全部保留。点击架上工件按身份取用，保留几何、材料、温度和工艺历史；陈列缩放不改变物理数据。

选料入口底部的“携带工件前往”保留同一会话并进入已有工位；左侧八项中控台仍打开独立固定样本，会重置当前会话。刷新同样重置，本轮不新增浏览器存档。

`physics-3` 修正新领取钢料的尺寸来源：使用规则表的标准截面数，不继承当前钢料切割后的截面数。存档结构不变；旧参数版本的存档可读不代表旧操作跨规则重放结果相同，本轮未加入历史规则执行器。

### 2.2 切割

- 玩家可平移、旋转并允许材料伸出桌边；有限刀路只移除其实际扫过的锯缝，不自动延长到工件边缘。
- 未切断的材料保留为同一工件并呈现缺口；剩余材料产生独立连通组件时才分别生成工件，额外组件进入工作台。可连续多刀逐步切断连接。
- 全部保留工件体积与锯缝损耗之和等于切割前体积；材料来源与过程状态按源单元保留。
- R1 支持平面直线有限锯缝及其自然形成的槽口；不包含任意曲线切割、独立冲孔工具、局部三维切深或完整三维布尔。

### 2.3 焊合

- 玩家明确选择当前工件和一块工作台工件，合并后被选工件从工作台移除。
- 新工件保留双方材料区域与工艺历史，新增带接触面积、焊合温度和完整性的界面记录。
- 工件级材料参数按体积汇总，仅供当前降阶公式使用。
- `layerCount` 是操作历史摘要，不等于空间层状几何；R1 不宣称已实现完整大马士革、装罐、扩散或夹钢截面。

### 2.4 加热

- 炉内/炉外状态和经过时间形成热边界，温度随环境连续变化。
- 塑性、过热和氧化来自共享材料规则，不使用固定 `+X` 奖惩。

当前 `R1-C1S` 采用单件、固定火力、整件均温：点击炉口或钢坯一次，钢坯水平送入炉腔并持续加热；再次点击抽出，在承托台上观察热色、温度和过热提示。无需按住鼠标。进入、取出与重复加热保留工件身份、几何、质量和热历史。

炉子位于同一工坊右后方；炉底与前方承托台齐平，支脚接地，三个燃烧管沿炉体纵深排列。选料、切割、加热共用 `WORKSHOP_UNITS_PER_MM = 0.46`；原料不因换工位或进入炉口被放大，也不自动压缩到槽位。炉口和台面按材料尺度安排，近景镜头仅改变观察位置。其他遗留工序的模型比例仍需各自重构，不能视为已经统一。

当前时钟仅在加热工位前台推进，离开工位、窗口失焦或隐藏时暂停；离开炉子时工件先取出，已有温度继续供后续操作读取。不实现全局冷却、局部热场、插入深度玩法、燃料管理或多件同时加热。

### 2.5 锤击

- R1-D1 使用 `surface-hammer`：单击落锤，滚轮调力度，自由平移、平面旋转与连续纵轴翻滚。实际占据表面决定落点，224 × 104 mm 有限砧面和底部接触点估算支撑；允许两端伸出，但无支撑处不能敲。
- 32 mm 方锤驱动局部压缩和横向保体积流动，实际节点形变梯度的主伸长进入共享弹塑分配、机械功、应力与损伤。切割空隙、材料身份、质量和损耗账目保留；旧轴对齐锤击操作仅保留兼容。
- 温度本轮冻结，已有温度仍参与屈服与塑性计算。未切网格显示沿厚度方向的最小点阵跨度，切后工件显示真实占据外廓尺寸；应力/损伤是降阶指标，尚不自动产生裂纹碎片。
- 热锻与冷锻的因果方向必须不同，但 R1 不承诺工业精度或已覆盖所有锻打技法。
- 当前实现的数值近似、版本迁移与作者体验入口见 `HAMMERING_HANDOFF.md`；弯曲、扭转、端面镦粗、折叠和锤击中冷却后置。

### 2.6 淬火

- 淬火是由玩家实际浸入、移动、停留和取出形成的冷却边界；介质、浸没程度、轨迹速度、持续时间和入槽温度共同决定冷却结果。
- 水和油提供不同的基础换热强度；移动改变换热和均匀性，结果进入温度、颜色、硬化倾向、脆性、残余应力、变形和开裂风险。
- 同一工件可以多次进出并切换介质，每次过程保存介质、起始/结束温度、浸没与运动事实。首轮整件处理，暂不承诺完整流体、局部相变或复杂中断淬火。
- R1 记录可解释的工艺事实，不在核心里直接生成固定“硬度”“攻击力”或故事结论；详细共识见 `docs/QUENCH_HANDOFF.md`。

### 2.7 回火

- 追加回火温度事件，不覆盖以前的淬火或回火历史。
- R1 只保证事件可读、可序列化、可供后续模型消费，不提前确定硬韧映射。

### 2.8 研磨

- 玩家选择工件区域并连续研磨，改变覆盖、均匀度和 block 体积。
- 累计去除体积必须与总质量变化一致。
- R1 是降阶去料模型，不包含完整表面重网格、自由磨削角度或最终刃口微观几何。

## 3. 共享操作原语与覆盖边界

夹持、选中工件、旋转、送料、对齐、携带和放置是多个工位共享的操作原语，不单独升级为顶层锻造动词。锤头、砧面、支撑和输入方式应优先扩充现有能力，使拔长、镦粗、展宽、压薄、校直和收尖等行为从操作中涌现。

八类足以覆盖 R1 金属工件基础，但不等于完整武器制造。冲孔/漂孔、扭转、折弯、复杂折叠焊、装罐与脱罐、热切与錾切差异、护手与剑柄装配、装饰、铭文、镶嵌、铸造和魔法工艺均未由 R1 完整覆盖。未来先判断它们是现有能力的工具/参数扩充、共享原语，还是确有独立目标与状态边界的新顶层能力。

## 4. R1 验收规则

每项固定样本至少证明：

1. 玩家通过对应工作站完成真实操作，而不是点击文字直接结算。
2. 一个关键输入变化会导致符合因果方向的不同原始状态。
3. 合法但不合适的操作可以发生并留下较差后果；未定义输入会被拒绝。
4. 同一初始状态和操作序列得到相同 JSON，可序列化后往返不变。
5. 自动测试检查真实状态、守恒和对象选择；作者亲自判断操作、反馈和画面是否达到当前阶段标准。

八项均由作者通过后，再做完整链回归并归档 R1。在此之前不得宣称玩法、真实感或 R1 已成立。

## 5. 下游契约

```text
ForgeState -> ForgeFacts -> host-owned profile -> host-specific attributes or rules
```

`ForgeFacts` 只暴露锻造事实。动作游戏可以计算攻击、破甲或防御；冒险游戏可以设计六维或故事条件；奇幻游戏可以引入魔法承载，但这些名称和公式不进入 `ForgeState`。

R1 之后只先做一个很窄的下游样例，检查现有事实是否足以产生有意义且可追溯的差异。六维和故事只是候选消费方式，不是已经锁定的下一阶段设计。
