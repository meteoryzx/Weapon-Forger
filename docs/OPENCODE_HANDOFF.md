# OpenCode 接手入口

本文件由项目级 `opencode.json` 自动加载，只负责告诉接手模型从哪里取得事实、当前停在哪里以及怎样继续。它不覆盖根目录 `AGENTS.md`。

## 每次新会话的读取顺序

1. 完整读取根目录 `AGENTS.md`，执行其中的远端、治理、检查点、验收和 Git 闸门。
2. 完整读取根目录 `PROJECT_PLAN.md` 的“唯一当前检查点”和与当前任务相关的章节。
3. 处理锤击、形变、铁砧或下一工序时，完整读取 `docs/HAMMERING_HANDOFF.md`。
4. 涉及公共状态、几何或数值时，再读 `docs/FORGE_SYSTEM_SPEC.md`、`docs/FORGE_CORE_API.md`、`docs/FORGE_UNIFIED_PHYSICS.md` 和相关 ADR；不要一次加载无关文档。
5. 用代码、测试、当前 Git 状态和 GitHub 远端交叉核对文档。发现冲突时按 `AGENTS.md` 的权威顺序停止并报告。

OpenCode 原生读取仓库根目录 `AGENTS.md`。不要运行 `/init` 重写它，也不要生成另一份项目规则。模型、供应商和推理强度由作者在客户端选择，本仓库不写死渠道 ID。

## 代码进度与事实边界

核心数据流是：

```text
平台输入 -> ForgeIntent -> ForgeOperation -> ForgeState
                                           |-> ForgeSnapshot -> render
                                           `-> ForgeFacts -> host-owned profile
```

- `src/forge` 保存确定性规则、材料、几何、温度、力学状态、历史和事实出口。
- `src/app` 保存工位级摆放和应用编排；`src/render` 只表现快照；`src/entry` 与 `src/platform` 翻译浏览器/微信输入。
- `WorkpieceGeometry.solids` 是有限切割后的实际占据实体；平面 `outline` 是派生凸包，不能填回缺口或代替材料占据。
- 切割后的材料来源、温度、应力、损伤和累计机械功随实体保留；`cutLosses` 单独记录锯缝去料。
- 当前热模型是单件整件均温。不要擅自恢复此前讨论过但被作者删去的局部加热、燃料或多件并行。
- 现有锤击求解器有可复用的材料响应、力学事实和确定性测试，但输入、姿态、拾取、接触与支撑仍是旧模型。详见 `docs/HAMMERING_HANDOFF.md`。
- 保存与回放必须尊重 `stateVersion` 和 `parameterVersion`；不要通过猜测数据修复不兼容的旧有限切割存档。

代码存在只证明仓库中有实现，不证明作者已验收。作者验收状态只以 `PROJECT_PLAN.md` 为准。

## 产品与空间共识

- 《打了个铁》要提供可组合的锻造操作和可解释的原始事实，不是固定配方、点击领奖励或无限拟真的材料软件。
- 硬目标有两个：玩家最终能够通过受支持的操作打造想要的形状；相应数值、因果和规则清楚，可用于系统策划作品与后续宿主玩法。
- 八个工位始终属于同一间连续工坊。近景通过移动观察位置突出工位，不创建八个房间。
- 当前大体布局：材料架后左、加热炉后右、切割台左前、铁砧中央。已有近景的空间关系以当前代码和已验收画面为准。
- 选料、切割和加热统一使用 `WORKSHOP_UNITS_PER_MM = 0.46`；标准钢坯为 336 × 48 × 8 mm。其他旧工位不能继续沿用不一致比例。
- 世界是低魔法、早期机械化工坊；设备可使用水力、蒸汽、齿轮、皮带或配重，但应像当地工匠能制造维修的铸铁、木材和铜件设备。
- 当前 R1 视觉目标是把比例、接触、朝向、操作对象和结果表达正确；正式模型、材质、动画、音效和整体精修后置。

## 开发与模型切换约定

- 新功能仍按“grill 共识 -> 参考图提示词 -> 作者确认参考图 -> 检查点批准 -> 实现 -> 自动审查 -> 作者体验 -> Git 归档”推进。
- 长任务或关键阶段开始前，先向作者推荐一个模型、推理强度和理由，然后暂停；作者切换并回复“继续”后才执行。
- 普通短操作沿用当前模型，不为每次“继续”“批准”或小修改重复打断。
- 日常讨论、示意图约束和边界清楚的实现优先使用中档模型；几何、接触、形变、数值规则、公共状态/存档契约和复杂故障优先使用旗舰模型高强度。
- 模型切换不等于重新开始。继续读取同一检查点、Git 差异和本文件，不重复已完成工作。
- 每个检查点只由一个主执行者写入。Codex、OpenCode 和 DeepSeek 不同时修改同一工作树或同一分支。

## 验证与 Git

- 基础检查入口：`npm run check`；浏览器交互回归：`npm run test:e2e`；文本差异：`git diff --check`。
- Node 版本要求见 `package.json`。不要仅为修复环境差异修改依赖或锁文件。
- 测试生成的截图和构建产物不是产品事实；人工体验结果不能由自动化代签。
- 作者要求提交后，按获批检查点完成创建分支、提交、推送、PR、CI、合并与短期分支清理，不把中间 Git 操作逐项交回作者。
